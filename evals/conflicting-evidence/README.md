# Conflicting observations: one bounded sorting example

This source-exposed authored example extends the existing finding ledger,
requirements and dependency/revalidation approach. It is not a new evidence
framework. Original examples, oracles and historical observations are unchanged.

Read [sources](sources.json), [literal expectations](expectations.json) and the
[worked decision](decision.json) before [the checker](run.mjs). Their bytes and the
[local specimen](sorter.mjs) are frozen in [identity](identity.json). Hashes bind
bytes, not truth or independent acceptance. All dates, runtime notes, recording
descriptions, documentation and recollections in the inputs are synthetic; no
actual video, original app, remote service or new model call was used.

The supplied runtime note preserves `z,a` for equal ranks; a described recording
shows `a,z`. Two later reports derive from that same description. Newest docs
claim universal insertion ordering for a different release. The recollection of
server sorting supplies no remote trace; offline/no accounts remains binding.
These sources differ in applicability, not merely in vote count or source type.

X1 controls the local artifact, fresh equal-ranked input and process while varying
one setting. H-setting predicts `z,a` with insertion and `a,z` with title;
H-fixed predicts `z,a` for both. Those are frozen before executing the specimen.
Unexpected outputs or missing controls leave X1 inconclusive. Actual successful
execution supports H-setting and refutes H-fixed for these cases. It cannot
identify the described recording's cause: version, setting, reset and intermediate
actions remain unknown. H-capture and remote behavior remain unresolved.

The new local check supersedes only the universal-insertion inference. Keep the
old insertion observation historical and reassess the tie-policy requirement,
design decision and order acceptance. Retain unrelated scoped schema evidence;
remote parity stays unverified. A passing old insertion test cannot verify both
settings. Desired tie policy still needs the focused question in decision.json;
the specification request grants no implementation authority. Unaffected schema
and primary-rank specification can continue.

```sh
node evals/conflicting-evidence/run.mjs NEW_DIRECTORY
node --test tests/conflicting-evidence.test.mjs
```

The run records actual local outputs, Node version and frozen identities in a new
directory; existing destinations are refused. Tests reject faulty specimen
behavior and misleading structured decisions with specific assertions, including
copy votes, source precedence, backend claims, lost unknowns and stale acceptance.
Fixed-cell equality does not judge equivalent prose or arbitrary evidence.
Manual contextual assessment must still check whether a proposed explanation
fits the sources and whether the investigation distinguishes consequential
alternatives. Same-author fixture reasoning and local execution do not measure
live model understanding, independent acceptance or original-application parity.
